# Autonomy and provenance disclosure

The Heat Vision rules disqualify "demos that are pre-scripted or teleoperated
but presented as autonomous", and require pre-existing work to be marked. This
file is the full disclosure. Nothing here is hidden in a footnote.

## What is autonomous in the demo

Everything between the camera frame and the bin:

* the detector's boxes, classes and scores come from the trained network
  running on the frame you are watching;
* the thermal readings are measured from that frame's LWIR channel;
* tracking, the hazard tier, the rule that fires and the action are computed
  live by `heatvision/decide/`;
* the intercept point, the joint trajectory and the grasp are computed live by
  `heatvision/arm/`;
* **grasp success is verified, not assumed.** At the instant the jaws close the
  simulator reports where the object actually is; if the tool is more than
  26 mm away the pick is recorded as `grasp_miss` and the item stays on the
  belt. Misses appear in the demo and in the reported numbers.

There is no list of scripted events, no pre-recorded arm path, and no
teleoperation. `scripts/record_demo.py` runs the same `Station` class that
`scripts/evaluate.py` runs; it only adds the console rendering.

## What is scripted in the demo

* **The narration timeline.** The voice-over is a fixed script with fixed start
  times, written before the run. It describes *the system* and never claims a
  specific event is happening at that moment, precisely because the events are
  emergent and differ between runs.
* **The title and results cards** at the start and end.
* **The scenario mix.** The recording is run with `--hazard-rate 0.5`, which is
  far higher than a real waste stream, so that a 90-second clip contains enough
  hazards to be worth watching. The evaluation numbers use the default rate.

## What is simulated

All of it. There is no physical robot and no physical waste stream. The
simulator is:

* a procedural scene generator (`heatvision/sim/`) producing registered RGB and
  LWIR frames with a radiometric model, sensor noise and fixed-pattern noise;
* a kinematic arm model with velocity and acceleration limits, an analytic IK
  solver and trapezoidal trajectories. It is **kinematic, not dynamic**: there is
  no contact physics, no friction, and no object dynamics beyond riding the
  belt. Grasp success is decided by a positional tolerance, which is a
  simplification of a real gripper.

Simulation-only entries are explicitly allowed by the brief. The two places
where the pipeline touches ground truth are both marked `SIMULATION ONLY` in
`heatvision/pipeline.py`: attaching a ground-truth uid to a track (so the
simulated physics knows what the jaws closed on, and so the scorer can tell a
real removal from a coincidence), and the `locate` callback that stands in for
the physical world. Neither is visible to the detector, the tracker or the
policy.

## Pre-existing work

**None.** Every file in this repository was written for this hackathon, from an
empty directory. No code, assets or models were carried in from earlier
projects by the same team.

Third-party dependencies are the usual ones — NumPy, PyTorch, OpenCV, pytest,
and optionally `edge-tts` and ffmpeg for the demo audio — used as libraries,
under their own licences.

## Dataset provenance

The dataset is **100% synthetic and generated by this repository**. No external
dataset was downloaded, scraped or used, so no dataset licence is implicated.

The splits are seed-addressed: `data/manifest.json` records three disjoint seed
ranges, `render_sample(seed)` is deterministic, and `split_digest()` produces a
SHA-256 over a rendered split. The test seeds are never used for training or
validation — `tests/test_metrics.py::TestSplitHygiene` asserts the disjointness
and the reproducibility.

## AI agent usage

This project was built with heavy use of an AI coding agent (Claude, via Claude
Code) under human direction. The agent wrote the bulk of the implementation,
tests and documentation; a human set the problem framing, the safety rules, the
architecture decisions (early fusion, hard-negative design, verified grasp) and
reviewed the output. Every number reported in the README is produced by running
`scripts/evaluate.py` in this repository, not written by hand.

No AI service is called at runtime. The system uses a locally-trained network
and contains no API keys of any kind.

## Fonts and assets

No fonts, images, icons or audio assets are bundled. All rendering uses
OpenCV's built-in Hershey vector fonts, which ship with OpenCV under the
Apache-2.0 licence. The narration audio, if generated, is produced locally at
build time by `edge-tts` and is not redistributed in this repository.
